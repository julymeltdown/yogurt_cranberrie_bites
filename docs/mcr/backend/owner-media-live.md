## Typed composition boundary

`OwnerMediaIdentity { actor, event, session_family, request_id, deadline: AuthorityRpcDeadline }` must come solely from the transport's verified product delegation. `OwnerMediaRequest::from_verified(identity, operation, method, target, content_type, idempotency_key, body)` checks closed schemas and exact C04 route binding. It does not authenticate the caller or manufacture authority. The transport must verify the exact original signed raw method/target/body/content-type/key before invoking it; enforce credential/access expiry, same-origin browser mutation intent, bounded streaming/concurrency and no credentials in URLs/logs. Empty content type/key/body are required for GET.

`OwnerMediaRuntime::new(pool, sanitizer, keys, Arc<dyn OwnerMediaFence>)` has no successful default fence. Sanitizer is `BoundedImageSanitizer::new(AdmissionClass)` from the retained CPU pool, with image-only 10 MiB input/output, 4096 per dimension/16 million pixel bounds, real decode/reencode and metadata stripping. Keys are explicitly configured `Arc<FingerprintKeys>` with active and retained HMAC signing keys; fixture keys are never startup defaults.

`dispatch(request)` returns `OwnerMediaReply::Json { status, body }` or `Image(PrivateImage)`. JSON is an explicit closed C04 projection. Binary uses `PrivateImage::headers()` (declared image MIME, private/no-store, nosniff, inline, same-origin resource policy). All errors and JSON must be no-store. Error messages must be fixed and must not include SQL, request bodies, private images, credentials or database URLs. The composition owner owns C04 error/status validation and original delegated HTTP authority.

Supported operations are `initConcertUpload`, `putConcertUploadBytes`, `finalizeConcertUpload`, `getConcertMedia`, `readConcertMedia`, and media-only `getConcertCommandStatus`. No extra intent endpoint, presigned upload, public URL or linkage operation is invented. Initialize returns the C04 same-origin PUT intent; PUT returns UPLOADED revision; finalize and metadata return READY metadata; content returns sanitized private bytes only.

Command status uses the canonical event `/commands?operation_id=...&idempotency_key=...` query. Only the three media command IDs are accepted; duplicate/unknown/missing parameters are denied. Actor comes from the verified request. Target media ID is resolved internally from the actor/event/operation/key receipt scope, then current target authorization gates the retained safe receipt. A missing receipt means RESOURCE_UNAVAILABLE, never nonexecution or rollback; this path never reexecutes a mutation or invents a new key.

## Authority and transaction behavior

`OwnerMediaFence::run(Arc<OwnerMediaBinding>, OwnerMediaWork)` must run the work exactly once inside a qualified durable canonical owner guard scope. The binding includes actor/event/session family/request/original wall+monotonic deadline, operation, exact method/target/content type/key and raw body SHA256, with a domain-separated length-prefixed digest. `OwnerMediaGuard` supplies that exact digest, a stable owner security revision, and `authorize_in(connection,binding)`.

The canonical implementation must establish current account eligibility and live session family, then order account deletion/deactivation, revocation, expiry and other eligibility changes against all producer/read/recovery transactions through commit. Signed observations, current-read responses, invalidation hints, heartbeat streams and simple expiring leases are insufficient. A dropped work future, owner crash, network failure or uncertain COMMIT must quarantine the guard until durable producer settlement proves the outcome; dropping a guard must not silently release exclusion. The owning authority lane is designing this protocol. This patch supplies no production success implementation and must remain disabled until that owner and real transport are qualified.

The runtime adds event SHARE, admission SHARE and participant SHARE locks on the same producer connection; only ACTIVE admissions and existing participants pass. Mutation phases are OPEN/LIVE; READ_ONLY denies new mutations. Owner reads and receipt recovery may remain permitted in READ_ONLY under fresh authority; ARCHIVED is denied. Producer rechecks current event/restriction/security revisions and immutable media purpose. Only actor-owned, unlinked media is allowed. Any linked target, foreign owner, Link or Delete access fails closed, including POST/GIVEAWAY/REPORT target audiences. Purpose labels alone grant no public/reporter/moderator access.

A single original monotonic deadline surrounds acquisition and all work. Timeout is an uncertain outcome. A successful BE15 execute means the local receipt/effect/outbox transaction committed; a later metadata/intent read may still fail, so an HTTP error does not prove mutation rollback. Canonical settlement must inspect the original scoped receipt and producer transaction outcome while retaining exclusion. Existing producer expiry clauses, idempotency hash, compare-and-set revision, quota and rollback guards remain authoritative.

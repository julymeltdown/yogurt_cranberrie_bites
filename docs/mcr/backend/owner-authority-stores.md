## Behavior and integration

Acquire requires authenticated Concert and its dedicated signed assertion, including actor/body and original budget. Concert is responsible for verifying the sealed original Gateway parent; the owners do not independently authenticate that parent. The immutable shared binding fingerprint excludes enrollment subjects. Prepared source SHARE transactions contain no ledger locks. A durable PREPARING reservation and exact preparer backend PID/start/xid are committed before preparation permission; only after PREPARE and the ACTIVE ledger commit is a capability granted. All pending and quarantined guards count toward the local cap of sixteen. PostgreSQL must support at least sixteen prepared transactions; actual cluster capacity is also checked before reservation.

Check and Enroll serialize on the ledger row and read actual owner facts without reacquiring a source SHARE behind a waiting writer. Enroll accumulates up to 100 distinct other subjects plus actor and returns the entire set. Auth uses real active account, live canonical session family through binding expiry, and permanent per-user security generations; active users lacking real generations fail closed, unknown subjects are inactive with generation zero. Friend returns actual tombstone/block state; `session_live=true` certifies Friend source eligibility, not Auth session validity.

Track requires the actual matching Concert/Post/Profile caller, a configured producer endpoint, and a structurally exact captured transaction identity. Identical retries return the same registration ID. Complete is Concert-only with an independent completion capability. It seals before resolution, rejects further registration/enrollment, and resolves the root scope plus every participant through the configured authenticated producer. Unknown/in-progress outcomes retain prepared locks after expiry, cancellation, process loss and restart. Terminal scope and receipt evidence commits before ROLLBACK PREPARED. Recovery can safely retry release if the process fails between release and COMPLETED. Ungranted PREPARING recovery verifies exact transaction/prepared state; absence of a backend alone is not proof of abort.

Each operation has one original monotonic budget including pool, method guard, decode and all SQL. Normal maximum is five seconds; completion and each recovery sweep are bounded at two seconds and can run after admission expiry for cleanup only. Capabilities and SQL errors are not exposed in diagnostics. Success responses carry `cache-control: no-store`.

The new service constructs its own restricted caller registry; retained Auth/Friend method registrations remain unchanged. Configure `CONCERT_SERVICE_CREDENTIAL` and, when used, `POST_SERVICE_CREDENTIAL` / `PROFILE_SERVICE_CREDENTIAL` with their rotation counterparts. Missing optional credentials deny those callers. Enable explicitly with `CONCERT_OWNER_AUTHORITY_ENABLED=true`, configured internal mTLS, `CONCERT_RELATIONSHIP_VERIFYING_KEYS`, and required `AUTHORITY_CONCERT_SETTLEMENT_ENDPOINT` HTTPS endpoint. Optional `AUTHORITY_POST_SETTLEMENT_ENDPOINT` and `AUTHORITY_PROFILE_SETTLEMENT_ENDPOINT` enable those producer registrations; absence fails their Track calls closed. Startup checks durable support/orphans and attempts bounded recovery; supervised periodic recovery continues every 250 ms. Readiness checks the owner ledger/prepared support. Unknown quarantines remain visible and capacity-bounded.

Auth 0017 adds tombstone-preserving per-user generations. Retained hard-delete UUID retirement and active-account session insertion rules remain enforced; the new counter does not authorize UUID reuse. Account insertion/deletion and security tuple changes increment only the affected user. Login/session insertion and legitimate refresh rotation preserve the generation. Deferred rotation classification verifies the actual same-family successor, not just a ROTATED label; revocation increments. All counters roll back with the actual mutation. Retained journal semantics remain separate and coarse.

## Negotiation and authoritative meaning

Authenticate may opt in with `motionProfileVersion: "1.0.0"`. Omission preserves the original closed C05 frame shape. Unsupported, null, nonstring or unknown fields still fail strict ingress. The selected profile appears only on a successfully admitted opted-in snapshot, together with `selfMotion`. If the server cannot provide its source-bound profile, it uses the original authoritative-only snapshot shape. This fallback grants no prediction capability. A geometry hash mismatch at the consumer likewise disables prediction.

The actual validated C06 `map_manifest.geometry_hash` is forwarded at production startup to the existing serialized owner. Profile speed comes from that owner's actual `Limits`, rather than a separately invented client constant. The profile declares 50ms steps, unit-disk analog axes, point-supercover all-or-nothing collision, at most four latest due steps, discarded older due ticks and the inclusive `age <= holdMs` rule. Existing event/room/stream/epoch and map identity fields bind the profile to its complete snapshot baseline. It creates no ticket, membership, authorization, physical arrival or domain command authority.

Each opted-in snapshot and delta carries a complete `selfMotion.position` at its exact `serverTick`, including deltas without a self upsert. `consumedInputSeq` is the inclusive highest queue removal, including expired/coalesced input; it is distinct from legacy `ackInputSeq`. `inputAppliedTicks` counts actual applications of the acknowledged input, including neutral or collision-blocked outcomes; it resets when the ACK changes. `droppedTicks` counts discarded due ticks cumulatively within the room epoch. `heldInput` exposes only sequence, axes and nonnegative remaining hold at the same serialized capture; no interaction flag, command, arrival clock or per-input history is exposed.

The complete anchor replaces the recipient's cached self position when a delta omits the self upsert. Equality is required with an initial snapshot's self row or an explicit same-frame self upsert; a conflict is rejected. FE17 identified that the first oracle incorrectly compared anchors against stale cached positions. The corrected oracle has both a changed-position/no-upsert positive case and a conflicting same-frame-upsert negative case. Existing fixture bytes are preserved; all 37 existing realtime tests and seven motion contract tests pass.

Stream replacement clears pending input, held/one-shot state, ACK, consumption and application duration. It preserves the room's discarded-tick counter. A new room epoch starts a new counter. Revocation removes the player and its motion anchor through the existing authority fences. Prediction is explicitly tentative and bounded, corrected at each authoritative anchor; neither ACK progression nor a server-tick jump describes an exact input-arrival schedule.

# HTTP contract — profile, room, intro post, likes, and media operations

Status: **CONTRACT_READY (proposed)**. Freezing this document is WP-01. Any
change after freeze is a dated decision in the charter's decision log.

## 1. Conventions inherited from the MCR contract system

These are already enforced by the foundation and must not be relaxed:

| Convention | Source |
| --- | --- |
| Every operation is declared in `contracts/domain/v1/operations.json` (or `contracts/core/v1/operations.json` for core identity/profile) with `operationId`, `method`, `path`, `request`, `request_location`, `response`, `success_status`, `actor`, `rule`, `write_policy`, `idempotency_key`, `retry`, `cache_control`, `errors`. | `contracts/domain/v1/operations.json` (117 operations today) |
| Schemas live in the matching `*.schema.json` under `$defs`, with `additionalProperties: false`. | `contracts/domain/v1/social.schema.json` etc. |
| Opaque IDs are canonical lowercase UUIDs. No prefixed IDs. | `contracts/domain/v1/common.schema.json#/$defs/Uuid` |
| Timestamps are UTC ISO-8601 ending in `Z`. | `common.schema.json#/$defs/UtcTimestamp` |
| Mutations carry `expected_revision` and are checked in the same transaction. | `policy.json` common guards |
| Personalized, secret, and domain responses are `Cache-Control: no-store`. | `policy.json` common guards |
| Errors use the closed code set; a denial for a private target is `RESOURCE_UNAVAILABLE`, never a distinguishing 403. | `policy.json` `http_error_status` |
| Bounded bodies per operation; the gateway rejects unknown query fields. | `api-gateway/.../concert_product/feature_routes.rs` |
| Browser mutations require an allowed `Origin` and `X-MCR-Intent`. | `policy.json` common guards |

Generated artifacts (`contracts/generated/*.openapi.json`,
`frontend/src/generated/api-client/`) are regenerated by
`backend/scripts/docs/generate-mcr-domain.py` and
`scripts/mcr/generate-api-client.py`. Never hand-edit them.

## 3. Schema definitions (new or extended)

Names are added to the existing schema files. Every object is
`additionalProperties: false` with an explicit `required` list.

### 3.1 `core.OwnProfile`

```json
{
  "profile_id": "Uuid",
  "account_id": "Uuid",
  "nickname": "string 1..40",
  "bio": "string 0..160 | null",
  "profile_image_media_id": "Uuid | null",
  "visibility": "PUBLIC | PRIVATE",
  "favorites": { "music": [FavoriteItem], "anime": [FavoriteItem], "games": [FavoriteItem] },
  "avatar": "AvatarState",
  "room_summary": { "visibility": "PUBLIC | PRIVATE", "decorated": "boolean" },
  "created_at": "UtcTimestamp",
  "updated_at": "UtcTimestamp",
  "revision": "Revision"
}
```

`FavoriteItem` = `{ "catalog_item_id": "Uuid", "label": "string 1..80",
"category": "MUSIC|ANIME|GAME", "external_url": "uri|null" }`.
At most 5 per category; `category` must match the containing array.

### 3.2 `core.PublicProfileV2`

```json
{
  "profile_id": "Uuid",
  "nickname": "string 1..40",
  "bio": "string 0..160 | null",
  "profile_image_media_id": "Uuid | null",
  "avatar": "AvatarState",
  "favorites_public": [FavoriteItem],
  "shared_with_viewer": [FavoriteItem],
  "interaction_style": "string 0..120 | null",
  "follow": { "following": "boolean", "followed_by": "boolean" },
  "blocked": "boolean",
  "room_available": "boolean"
}
```

- `shared_with_viewer` contains only items the viewer also selected. It is the
  source of the "You both love MCR and NANA" line. It is empty when there is no
  overlap, and the client must then show no shared-interest claim.
- `interaction_style` is omitted (`null`) when the user did not set one.
- No age, gender, or audience field ever appears here.

### 3.3 `social.IntroPostDetail`

```json
{
  "intro_id": "Uuid",
  "author": "core.PublicProfileV2",
  "body": "string 1..1000",
  "favorites_snapshot": [FavoriteItem],
  "currently_seeking": "string 0..120 | null",
  "interaction_style": "string 0..120 | null",
  "attachments": [ "feed.Media" ],
  "like": { "count": "integer >= 0", "liked_by_viewer": "boolean" },
  "comment_count": "integer >= 0",
  "published_at": "UtcTimestamp",
  "expires_at": "UtcTimestamp | null"
}
```

Deliberately absent: `audience`, `minimum_age`, `maximum_age_exclusive`,
`allowed_gender`, `room_id`, `like_count` for restricted viewers, and any
external-account field. The audience is author-only.

  "audience_summary": "string 1..80",

`audience_summary` is server-derived (for example `Women · Ages 18–29`). The

### 3.5 `social.IntroLikeState`

```json
{ "liked": "boolean", "like_count": "integer >= 0" }
```

For `DELETE` when the viewer no longer satisfies the audience, the response is
`200 { "liked": false, "like_count": null }` — `like_count` is nullable **only**
on that path, so that removing your own heart never reveals the current count.
`PUT` on a post the viewer cannot view returns `404 RESOURCE_UNAVAILABLE`.

### 3.6 `social.LikerPage`

```json
{
  "items": [{
    "profile_id": "Uuid",
    "nickname": "string 1..40",
    "profile_image_media_id": "Uuid | null",
    "avatar": "AvatarState",
    "shared_with_author": [FavoriteItem],
    "interaction_style": "string 0..120 | null",
    "liked_at": "UtcTimestamp"
  }],
  "next_cursor": "Cursor | null"

```

Author-only. `403 PERMISSION_DENIED` for anyone else. Blocked, deleted, or
otherwise inaccessible likers are omitted, and the page may therefore be shorter
than `limit`.

### 3.7 `social.ProfileRoom` / `social.OwnRoom`

```json
{
  "owner_profile_id": "Uuid",
  "visibility": "PUBLIC | PRIVATE",
  "layout": "RoomLayout",
  "posters": [ "feed.Media" ],
  "revision": "Revision",
  "updated_at": "UtcTimestamp"
}
```

`social.OwnRoom` adds `"is_owner": true` and the moderation state of each poster.
A visitor of a `PRIVATE` room receives `404 RESOURCE_UNAVAILABLE`; the profile
still reports `room_available: false`.

### 3.8 `social.SaveRoom`

```json
{ "expected_revision": "Revision", "layout": "RoomLayout" }
```

`409 REVISION_CONFLICT` returns the current `social.OwnRoom` body so the client can
offer an explicit resolution.

### 3.9 `social.UploadPoster`

```json
{
  "preset": "FINE | CHUNKY",
  "width": "integer 8..128",
  "height": "integer 8..128",
  "content_type": "image/png",
  "bytes_base64": "string 1..1048576"

```

The server validates PNG signature, dimensions, and that the image is a valid
PNG, then stores it as a room-poster media asset. It does not re-pixelate.

### 3.11 Notification extension

`Kind` gains `INTRO_LIKED` (wire value `7` in
`backend/proto/notification/v1/concert_inbox.proto` and
`concert_delivery.proto`), and `TargetType` gains `INTRO_POST` (next free value
after `REPORT`). Both are additive; existing values keep their numbers.

`Kind::IntroLiked.safe_summary()` = `"Someone liked your mutuals-intro post"`.
The actor's nickname is rendered from the resolved profile, never interpolated
from stored free text.

## 4. Validation rules

| Field | Rule | Failure |
| --- | --- | --- |
| `body` (intro) | 1..1000 chars when published; 0..1000 in draft; no NUL; contact-bypass rules of the existing `intro_policy::contact` apply | `400 INVALID_INPUT` |
| `currently_seeking`, `interaction_style` | 0..120 chars, single line, no NUL | `400 INVALID_INPUT` |
| `audience` | bounds paired; `minimum_age < maximum_age_exclusive`; `allowed_gender` in the closed set | `400 INVALID_INPUT` |
| `attachment_media_ids` | ≤ 4; unique; each owned by the author; each `READY`; each purpose `INTRO_POST` | `400 INVALID_INPUT` / `404` |
| `favorites` | ≤ 5 per category; catalog item must exist; music catalog excludes K-pop | `400 INVALID_INPUT` |
| `layout` | grid bounds; ≤ 4 posters; unique furniture cells per layer; known style IDs | `400 INVALID_INPUT` |
| media bytes | JPEG/PNG/WebP; ≤ 6 MiB; ≤ 4096 px per side; ≤ 16 M pixels | `415` / `413` / `400` |
| poster | PNG; ≤ 128 px per side; ≤ 1 MiB | `415` / `413` |

Media limits are aligned with the existing MCR media domain
(`concert-application/src/media/mod.rs`: `MAX_BYTES` 10 MiB, `MAX_DIMENSION`
4096, `MAX_PIXELS` 16 M). The product limit of 6 MiB is stricter than the
foundation's 10 MiB and must be enforced at the profile-media operation, not by
changing the shared constant.

## 5. Error mapping

| Situation | Status | Code |
| --- | --- | --- |
| Not authenticated | 401 | `AUTHENTICATION_REQUIRED` |
| Account context version mismatch | 409 | `ACCOUNT_CONTEXT_STALE` |
| Not the owner of the target | 403 | `PERMISSION_DENIED` |
| Post, room, or media exists but viewer is not authorized | 404 | `RESOURCE_UNAVAILABLE` |
| Audience conditions not met | 404 | `RESOURCE_UNAVAILABLE` |
| Attributes unevaluable | 404 | `RESOURCE_UNAVAILABLE` |
| Revision mismatch | 409 | `REVISION_CONFLICT` |
| Validation failure | 400 | `INVALID_INPUT` |
| Rate limit | 429 | `RATE_LIMITED` |
| Policy/claim source unavailable | 503 | `DEPENDENCY_UNAVAILABLE` |

The gateway already refuses to build a response for an undeclared status; new
operations must declare every status they can produce.

## 7. Client contract rules

- The client never decides visibility. It renders what the server returned and
  shows a neutral unavailable state for a 404.
- The client never sends an actor ID; the actor is the session.
- On `ACCOUNT_CONTEXT_STALE`, clear all account-scoped caches (drafts, uploaded
  media, avatar cache, room draft) before retrying.
- The intro composer keeps the draft locally on failure and offers retry, reusing
  the existing upload-then-publish sequence.
- Query keys must be identity-scoped: `['intro', accountVersion, introId]`,
  `['discovery', accountVersion, filters]`, and so on.

### B: proposed command and concurrency boundary

Proposed names/routes are illustrative **new** C04 operations, not fields added to `PlacePixel` or existing executable APIs. Retain the existing pencil endpoint. Add member-only `eraseConcertMuralPixel`, `fillConcertMuralRegion`, `undoConcertMuralAction`, via event-scoped `/mural/erase`, `/mural/fill`, `/mural/undo`, and an actor-owned action-result read. Every mutation requires captured canonical actor/event authorization, browser-origin/intent protections, an idempotency key bound to the exact body, and `expected_revision`. A separate/versioned, actor/event/revision-bound tool-capability read must supply server-qualified background index, availability, cost/quota and undo eligibility; it is advisory and cannot replace mutation authorization. Do not append fields to the existing strict snapshot while claiming old-client compatibility. Missing/unverified capabilities disable the affected tools.

- **Erase:** body contains one coordinate. Recommended B explicitly designates **palette index 0** as its immutable background role during B provisioning, retaining that palette entry's actual RGB value. This is a proposed semantic role, not a claim that today's index 0 is blank or white. Do not recolor the palette or existing mural to install it. The server-qualified capability must confirm the role before preview/commit; missing configuration disables erase. No transparency, image import or original-image reconstruction. A cell already at that color is rejected as no change without a new successful mutation/cooldown charge.
- **Fill:** body contains seed coordinate and replacement palette index. On the current locked grid the server computes the four-connected region of the seed's original color. Preview captures its base revision, affected count and color. Proposed cap: **256 changed cells**; reject an oversized region or same-color/no-change request as a whole, with no partial fill or queued individual placements. Every remote global revision change invalidates the draft or requires recomputation and explicit reconfirmation, including disjoint edits. Exact revision matching prevents an outdated preview from changing a newly connected region. Bounded compute/body/result/error limits need new closed schemas.
- **Undo:** body identifies an original action, not client-supplied previous colors. Server-private history stores its actor/event, before/after cells, action ID, committed revision and expiry. Include new pencil actions as well as erase/fill; no retroactive promise for history-less old operations. New pencil writes need an explicit private association to their original receipt/key/operation, exposed through the new authorized own-action lookup/result rather than extra fields in the old pixel acknowledgment. Recommended eligibility expires **10 minutes after the original commit**, or earlier if the original retained receipt expires. Keep the necessary private history for that window under the owning retention policy; a missing/retired record fails closed. Only the same actor's latest successful non-undo action may be compensated, and **current global revision must equal that action's committed revision**. Any intervening user's write, control/restore or later own action prevents undo, even elsewhere on the grid. No redo, stacking or moderator impersonation. Undo never rewinds history or restores cooldown.
- **Reload/re-entry:** recommended default is **server-owned recovery across authenticated reload**, not a browser-only undo stack. A fresh private latest-own-action read for the current canonical actor/event restores the single eligible committed target and any unresolved original action correlation. Recheck authorization, global revision, expiry, quota and cooldown; do not persist before-colors or action authority in local storage. Pending/unknown outcomes recover the exact original key/body/result before another mutation is allowed, including across tabs/sessions for that actor/event. If correlation or current policy cannot be verified, editing/undo stays unavailable rather than replaying or inventing history. Reload does not renew expiry, cooldown or budget; unrelated basic world use remains separate.
- **Transaction:** authorize current membership/policy and OPEN/LIVE event, lock the mural aggregate, recheck EDITABLE, deadline, cooldown/quota, revision and every affected region lock. For undo also check target ownership/expiry and current before/after binding. Commit all cells, private action history, receipt, quota/cooldown and outbox atomically; any failed check/DB error leaves no partial effect. Permission or policy failure does not become a positive local fallback.
- **Cooldown/fairness:** keep the existing server-configured cooldown once per successful action, including undo. Additionally enforce **512 changed cells per canonical actor/event in a rolling 10-minute database-time window**, shared across pencil, erase, fill and undo, all tabs/sessions and reloads. At the locked write boundary, count actual changed cells from successful actions committed in `(now − 10 minutes, now]`; admit only when that total plus this action's count is at most 512. No partial writes. Undo charges its restored-cell count too; it neither refunds the original cost nor reserves free capacity. A 256-cell fill with an otherwise empty budget leaves 256 cells for a possible undo; two such fills exhaust the window. Show affected cells, remaining allowance and the server's next availability before confirmation. Retry the same key without charging twice. Failed/no-change/conflicting commands spend no successful-action budget/cooldown; independent attempt rate limits still apply. If cooldown or quota prevents undo before its expiry, it remains unavailable, not exempt. Quota recovery derives from durable charge times independently of receipt lookup; record retirement cannot reset the budget.
- **Revision/recovery:** each successful action advances the global revision exactly once, including a compensating undo. A multi-cell action has no truthful existing single-pixel delta: advance the reset baseline and return `reset_required`, forcing a fresh authoritative snapshot for old/new clients. Do not fabricate one `PublicPixelOperation` or silently reuse its single-cell acknowledgment. New action results bind action/event/key/revision/count/server time/next allowed time; private history and authors never enter public snapshot/delta. Preserve unknown/pending outcome recovery before allowing another command.

### Heading and frontend impact

`THE BLACK PARADE` is **already-authorized static presentation content** from the supplied exact design, for both A and B. Keep the actual 128×128 grid, 16 server colors, revision/state and server-derived cooldown truthful in adjacent details. Neither the mural DTO nor current editor props carry an album/title field; that does not create another product permission gate for a static caption. The caption does not load the pictured illustration, recolor users' work, select another shared wall or imply event/era-derived metadata or authority. Keep it in presentation configuration; dynamic selection, per-event editable metadata and imported wall artwork remain outside this assignment.

A keeps the existing `editor/{MuralEditor,controller,contract}.ts*` and `sync/{controller,projection,http,contract}.ts*` protocol behavior. Caption-only work needs an explicit presentation configuration/prop and responsive/accessibility checks; any chosen Root-owned caller forwarding receives exact-path coordination, with no implied change to authority, owner, release or wire contracts. A static caption need not modify `MuralEntryRelease` or the canonical owner. Neither shell event title nor selected theme automatically supplies an event/era-derived wall heading; that separate metadata choice remains outside A/B. B needs typed action drafts/results instead of the single `PixelCommand`, bounded multi-cell preview and explicit confirmation/count/cost/conflict states, server-qualified undo eligibility, and reset/snapshot handling in the same shell-owned controller/world texture. Never infer undo permission from a browser stack or public author data. On logout/event/policy changes scrub previews/history; across ordinary panel navigation retain unresolved command identity. Labels must distinguish Cancel preview from Undo action and opaque erase from transparency; dragging must still never commit. Shared entrypoints, generated contracts and CSS retain their existing owners; this proposal grants no implementation paths.

## Decision requested

Choose **A or B**. **B is the developer's recommended complete bundle**; the user is not asked to design quota internals or reload behavior. A retains simpler one-pixel fairness but accepts missing reference tools. B enables small-area editing with explicit limits: “Fill up to 256 pixels; share 512 changed pixels per 10 minutes across all tools. Undo costs pixels too and is available for 10 minutes only while the wall is unchanged. Reload restores eligible actions, not extra quota.” Busy-wall changes, an exhausted allowance or cooldown can prevent undo. Both options use the already-authorized static caption. Transparent erasure, full-wall fills, selective undo across intervening edits, redo, dynamic album/event metadata and imported artwork are excluded from this recommended bundle. No tool implementation is authorized until the user makes the A/B product decision.

## Contract and behavior

`createWorldReplication` exclusively owns one injected idle `WorldTransport` and the captured canonical user/event/generation. It consumes FE16's validated frames, delivered sequence and reset decisions; it neither duplicates protocol validation/bookkeeping nor infers gaps from room-global ticks. Frozen C05 v1.0.0 schema/policy and generated FE16 wire types remain authoritative. C03 AvatarState/C06 AvatarConfig are forwarded unchanged as immutable public metadata; item/atlas allowlist qualification belongs to the eventual FE12 renderer, not a fabricated sprite fallback.

- INITIAL/RESYNC/ROOM_SWITCH/EPOCH_CHANGED snapshots atomically replace the roster. Only current metadata and players remain; `snapshot.players` is not retained as a second roster. Removals immediately remove their presentation state. Gap recovery clears displayed entities while awaiting the replacement snapshot, preventing stale ghosts.
- The entity sink receives immutable full replacements with public `WorldPlayer`, a separate presentation position, and self identity. No email/handles/physical meeting state is added. Self uses authoritative position immediately. Remote positions interpolate from current presentation to the latest authoritative endpoint over a bounded 100ms local presentation window (C05's 10Hz delta target), with no extrapolation, server-wall-clock assumption, history queue or movement simulation. There are at most 50 current entities and two presentation endpoints each.
- `setIntent` accepts only normalized axes and optional `interact`. Axes coalesce at the C05 20Hz simulation target, below its 30/s input ceiling. One-shot interaction is consumed once; it is discarded during resync, visibility loss and stream replacement. Idle neutral sends once, then installs no input cadence until another intent. The acknowledgement ledger holds at most 64 sequence numbers, clears consumed entries, and requests PROTOCOL_RECOVERY instead of growing or replaying. Every new stream resets input seq/ack and sends current held axes afresh; only ordinary resync/room replacement preserves held axes. Hiding clears them.
- FE16 alone validates sequences/epochs, authorization, ticket issuance, stream controls and timeouts. Its one `resync-needed` event drives one request, spaced by the frozen 1,000ms minimum using at most one controller timer. No second socket, heartbeat/watchdog timer, reconnect loop, ticket adapter or HTTP mutation queue exists. The controller answers the existing ping event using `clientPong`.
- A room-switch request leaves old-room roster/input authoritative until a replacement snapshot. Ordinary target-ticket failure or switchRejected retains that baseline. FE16 emits live before the replacement frame; a generation-fenced microtask defers state-only live publication so the old room is never committed as the new live baseline. A synchronous replacement snapshot wins that publication; ordinary pre-send denial still returns to live. `switchRoom()` returning true means request sent, not membership admitted; read the new baseline to observe success. Transport-terminal failure clears state instead of guessing the winning room.
- `setVisible(false)` cancels the current connection, input/resync timers, roster, pending inputs and held intent. The matching foreground transition performs one fresh connection/ticket attempt. Unexpected close waits for explicit `reconnect()`; there is no automatic retry/takeover loop. A typed MAP_VERSION_MISMATCH refuses reuse of the old resources: refetch/qualify assets and create a new owner. BACKPRESSURE permits explicit fresh-connection retry.
- Canonical identity/event/generation abort ends this controller, disposes its transport, clears projection/inputs/timers/listeners and fences late tickets. Revoke also ends the owner, including CONNECTION_REPLACED; an intentional takeover requires a newly constructed owner after explicit user action. Never automatically recreate it from a revoked old view. Disposal and sink failure clear authority; a throwing/reentrant sink or subscriber cannot leave a timer/connection committing stale entities.

### Spatial prediction prerequisite

C05 exposes serverTick and ackInputSeq, plus frequency targets. It does **not** expose authoritative speed, foot/collision policy, per-input duration or a deterministic simulation model. FE15's injected synthetic/local values are not authoritative BE12 parameters. Therefore the view exposes `spatialPrediction: 'unavailable'`; unacknowledged inputs reconcile the ledger, while local coordinates reconcile directly to authoritative upserts. No speed or clock physics was invented, no movement-policy wire extension was made, and no claim of spatial prediction completion is justified. A reviewed authoritative model/policy binding and renderer/local-prediction reconciliation port are prerequisites for completing that part of FE17.

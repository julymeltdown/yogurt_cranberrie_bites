## Production adapter

Construction is synchronous and performs no HTTP or subscription side effect. `read()` initially exposes the exact supplied bootstrap object, full frozen privacy scope and six false service flags. The caller explicitly awaits `prepare(signal?)`; `subscribe()` observes changes and `dispose()` releases the lease.

Preparation clears all old flags first and uses only the existing canonical Auth request client under `auth.privacy.run`. Each response must be an actual 200 at its exact path and identity generation and must pass the existing public contract decoder. Bodies are immediately discarded. The service reads are:

| Service | Actual public read prerequisites |
| --- | --- |
| feed | Concert feed page; C03 feed capability must also permit it |
| people | Published Intro page with event/row validation |
| intro | Own Intro with current owner/event binding |
| age | Own safe age-status response |
| inbox | Own notification list with safe event/row validation |
| requests | Both own handle-state list and own incoming request list; C03 sharing capability must also permit it |

A failed, malformed, cross-context or unavailable read leaves only its service false. Missing own Intro is unavailable rather than a fabricated positive. A successful UNKNOWN/UNSUPPORTED/PROVIDER_UNAVAILABLE age-status read makes that status readable; it never establishes a verified claim, eligible actor, approved consent, configured handle or mutation permission. Those still require actual server authorization and provider provenance. Empty real lists establish readable service readiness, not successful product flows. Refresh, policy change, identity/event/generation loss, caller abort and disposal cannot preserve or restore old positive readiness; late responses are fenced by the original scope and preparation generation. There is no new cache, Auth, World or socket.

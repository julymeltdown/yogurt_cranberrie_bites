## Delivery criteria

1. Each developer reads the working agreements, specification, assessment,
   execution plan and selected-character guidance; inspects its actual goal;
   creates an unbudgeted goal if no unfinished one exists; reports the actual
   status. Preserve incompatible unfinished goals rather than falsely closing
   them. Keep required implementation, validation, docs, handoff and fixes active.
2. Developers inspect existing immutable actual 390px screen captures and the
   reference before changing backgrounds. Record their paths, candidate revision,
   viewport, theme and fixture/live limitations. Request missing before frames
   through Root/coordinator, never duplicate a capture workflow.
3. After exact disjoint grants, implement only background surfaces/texture and
   noninteractive backdrop ornament. Preserve selected character pixels,
   source pack, crops, atlas, renderer, preview layers and all application guards.
   Do not impose a whole-World completion barrier on independent ready leaves.
4. Root and the implementation owners coordinate serialized bounded rendered
   passes: actual 390px before/after for a ready cohort first, then required
   360px and 430px checks across affected screens and relevant themes.
   Owners check existing text/background contrast, focus visibility, overflow,
   interaction, character readability and unchanged mural pixels. Report actual
   commands/exit codes and failures, with fixes owned by the developers.
5. Each handoff records source/contract revisions, base and delivered commits,
   exact paths, assets/dependencies/provenance, visible behavior, evidence and
   remaining limitations. Root publishes through a normal non-force master
   integration and verifies ancestry. No completion from a sent message alone.

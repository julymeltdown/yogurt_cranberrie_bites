# PI01 controller / receipt contract v1

This is an owner-local producer example, not a new allocator, shared executable
sampler, release certification or receiver approval stage. Existing allocator21d
finite offers alone authorize capacity. Each receiving developer adapts and
validates its own controls. Preserve selected model/reasoning and English.

## Actual identity and invocation

Use an absolute launcher, an absolute script argv, and the exact assigned cwd.
On this Mac the Python framework launcher and runtime have different paths:

- launcher: `/Library/Frameworks/Python.framework/Versions/3.14/bin/python3`
- observed `ps -p PID -o comm=` runtime:
  `/Library/Frameworks/Python.framework/Versions/3.14/Resources/Python.app/Contents/MacOS/Python`
- script: `/Users/lhs/Desktop/mcr-worktrees/fe-runtime-preferences/frontend/src/app/__tests__/parade-ink-foundation/controller.py`
- cwd: `/Users/lhs/Desktop/mcr-worktrees/fe-runtime-preferences`
- argv: `[absoluteLauncher, "-B", absoluteScript]`

`Path(sys.executable).resolve()` does not establish actual macOS runtime comm.
PI06 independently documented the same launcher/runtime inode distinction.
Never advertise a future executable or script as currently running. An inline
bootstrap records its actual Python/stdin identity before same-PID exec, then
the running absolute controller replaces that descriptor before heavy census.
Store actual PID, normalized `ps lstart` birth, comm, script and cwd. Match birth
before interpreting a live PID; reuse is not a valid identity. No process-absence
or wall-clock timeout is FULL. Accepted reservations remain charged without PIDs.

## Finite clocks and receipts

Capture `time.time()` immediately at actual bootstrap. Pass the same epoch into
the controller (`MCR_PI_ACCEPT_EPOCH`). Derive fixed WORK/FULL from that epoch
and the exact offered durations; neither exec nor another helper resets them.
The example native scope is 300 WORK / 360 FULL, including cleanup, 24 ALL PIDs,
3.5GiB RSS, 200MiB TOTAL positive NEW and 8GiB complete WHOLE, strict5365;
start/residual/live floors12/9/8GiB. These numbers are historical example caps,
not a grant to recipients. Retain every higher historical WHOLE high-water.
Charge full checkout, private/common Git, dependencies, Node, Chrome, complete
Python framework, output roots and retained own visualization; deduplicate
physical files and avoid subtracting carry already reflected in free space.
OTHER includes ordinary future upper2.5GiB plus outstanding peer growth.

Only this owner writes its own full-chat-ID JSON in the allocator's
owner-resource-receipts directory. Atomic temp+replace publication before work
contains ownerThreadId/offerId/state/actual acceptedAtEpoch/WORK/FULL/kind/caps/
remainingNewUpperBytes/controller/guardControllers/receiptPaths. The guardian
adds its actual descriptor before work. Publish actual FULL after cleanup and
send literal FULL directly before image inspection/docs. Record failed rounds
as failed; do not restart a closed offer or infer missing-PID release.

## Independent live census

Both existing guards independently read bounded owner receipts (128files,
64KiB each), reconcile legacy accepted claims and take a fresh untruncated PS
snapshot. They compute each controller's descendant closure from that ONE
snapshot, deduplicate helpers/process groups and check both declared reservations
and actual distinct PIDs/RSS. A missing new record does not delete an old claim.
Global maxima are4 workflows, SOURCE3, browser2, warm Rust target1, summed
96 PID caps and18GiB RSS. Per-guard atomic outputs are distinct:
`nativeNN-controller-census.json` and `nativeNN/guardian-census.json`.
Each contains observation epoch, PS snapshot SHA, owner set, actual PID/RSS,
reserved totals and peer positive-growth upper. This is not a frozen allocator
snapshot masquerading as live enforcement. Recognized unregistered scoped
Node/Rust/Python-script or headless Chrome roots fail closed; identity mismatch
reports owner/PID/birth/expected-script/observed-executable/command digest only,
not full possibly sensitive arguments.

Ordinary file/Git/preparation helpers are not validation workflows. The optional
nested `ordinaryObservation` preserves the last workload state/caps/clocks and
records exact actualpid/birth/cwd/role/observedAt/commandDigest/booking, then
endedAt/exit when known. It invents no execution cap or reservation. A receiver
may resolve ONLY that exact PID+birth and factual role/ancestry, counting actual
PIDs/RSS; a stale observation does not identify a new helper. Do not use a broad
cwd/basename exemption for unknown compiler/test/browser/script payloads.
This example's scope recognizer is not a universal macOS process classifier;
receivers must resolve their actual unknown roots, including otherwise opaque
shells, through factual owner descriptors rather than claim unexecuted coverage.

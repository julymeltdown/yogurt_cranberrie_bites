# Paradise City public API clients

The Notes objective is to deliver the frozen N01 public request/response projection, strict closed decoding, canonical shared HTTP registration and adapter, privacy cancellation, meaningful source checks, and a committed handoff. This objective is independent of the older IN04 goal; its status and evidence are preserved.

`notes.ts` exports `buildNotesRequest`, `createNotesClient`, and `createHttpNotesTransport`. Inject the shell's existing `HttpClient`, `SessionPort`, and query privacy coordinator. Construction performs no request. Every request borrows the full current privacy scope and signal; the adapter uses registered canonical HTTP operation IDs, protected session authorization, and caller-supplied command keys. It adds no fetch client, authentication, refresh, cache, timer, retry, or reconciliation implementation.

Actual provider landmark identifiers and numeric catalog/landmark revisions are distinct from illustrated map identities. A create requires a matching real landmark selection. Replies inherit their parent's audience and exact expiry. Withdrawal puts expected revision in the query. The wire value is `VENUE_END_DAY`; the client invents no timezone or midnight. Read leases, note expiry, parent identity, and thread inheritance are checked against server timestamps. UI capability adapters remain with the Map owner.

Successful canonical HTTP responses pass the operation decoder. Canonical transport failures remain `TransportError`, including its uncertainty and retry-after facts. A direct injected transport's declared error envelope is decoded into safe `NotesApiError`; raw messages and bodies are not retained there. An uncertain command is never resent automatically. Reconciliation requires the actual backend command-status routing for these new operations and the original command key; registration alone does not provide that routing.

Source authoring under the ordinary booking is not qualification. The tests cover actual request semantics, closed inputs, Unicode limits, response context, privacy withdrawal, and no retry. Their execution, strict TypeScript, lint, and generator drift checks require a separately admitted finite source run. Until its recorded result exists, these checks are NOT RUN. No service, browser, multiuser, device, physical location, end-to-end application, or VENU acceptance is claimed by this source delivery. All-response no-store remains a backend/runtime obligation; canonical HTTP's existing request cache policy is preserved.
